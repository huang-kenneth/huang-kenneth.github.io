Predicting Employment Status from Lifestyle Factors (NHANES)¶

Research question: Can self-reported alcohol use and physical-activity behaviors predict whether a respondent is employed? We combine three NHANES modules (ALQ, OCQ, PAQ), build a binary classifier, and then test whether the signal is statistically real.

NHANES encodes "Refused"/"Don't know" as runs of 7s and 9s (e.g. 7/9, or 7777/9999 for wider ranges). We detect and convert these to missing so they aren't treated as real values.

In [27]:
# Remove NHANES "Refused" (repeated 7s) and "Don't know" (repeated 9s) codes.
# For each column the code is the shortest run of 7s / 9s that exceeds every
# real value, e.g. 7/9 for codes 1-4, or 7777/9999 for a 0-1320 range.
def is_run(x, d):
    return x == int(x) and x > 0 and set(str(int(x))) == {d}

def special_codes(s):
    vals = s.dropna().unique()
    real = [v for v in vals if not is_run(v, "7") and not is_run(v, "9")]
    max_real = max(real) if real else 0
    refused = next((int("7" * w) for w in range(1, 10) if int("7" * w) > max_real), None)
    dont_know = next((int("9" * w) for w in range(1, 10) if int("9" * w) > max_real), None)
    return refused, dont_know

for col in df.columns.drop("SEQN"):
    if np.issubdtype(df[col].dtype, np.number):
        refused, dont_know = special_codes(df[col])
        df[col] = df[col].replace({refused: np.nan, dont_know: np.nan})

print(df.shape)

We recode raw survey codes into interpretable units (yes/no → 1/0, alcohol-frequency codes → drinking days/year, activity frequency×duration → minutes/week), and apply NHANES skip-pattern logic where an upstream "no" implies a structural 0 rather than missing.

In [28]:
# ---- Recode variables into meaningful units (per doc.md) ----

# Yes/No -> 1/0
for col in ["ALQ111", "ALQ151"]:
    df[col] = df[col].map({1: 1, 2: 0})

# Alcohol frequency code (0-10, same scheme across these four) -> drinking days/year.
# "Nearly every day" = 300; your example's 365/2 collided with code 3. Tune freely.
FREQ_TO_DAYS = {
    0: 0, 1: 365, 2: 300, 3: 3.5 * 52.18, 4: 2 * 52.18, 5: 52.18,
    6: 2.5 * 12, 7: 12, 8: 9, 9: 4.5, 10: 1.5,
}
for col in ["ALQ121", "ALQ142", "ALQ270", "ALQ280"]:
    df[col] = df[col].map(FREQ_TO_DAYS)

# ALQ130 (drinks/occasion) and ALQ170 (binge count, past 30 days) are already
# meaningful counts -> kept as-is and separate.

# Physical activity: frequency x unit x per-session minutes -> minutes/week.
UNIT_PER_WK = {"D": 7.0, "W": 1.0, "M": 12 / 52.1775, "Y": 1 / 52.1775}
def min_per_week(freq, unit, dur):
    mins = df[freq] * df[unit].map(UNIT_PER_WK) * df[dur]
    mins[df[freq] == 0] = 0.0  # never does it -> 0 (unit/duration are skipped)
    return mins
df["MOD_MIN_WK"] = min_per_week("PAD790Q", "PAD790U", "PAD800")
df["VIG_MIN_WK"] = min_per_week("PAD810Q", "PAD810U", "PAD820")
df = df.drop(columns=["PAD790Q", "PAD790U", "PAD800", "PAD810Q", "PAD810U", "PAD820"])
# PAD680 (sedentary min/day) is already clean -> kept.

# Structural zeros: NHANES skip patterns imply 0, not "missing".
df.loc[df["ALQ111"] == 0, ["ALQ121", "ALQ130", "ALQ142", "ALQ270", "ALQ280", "ALQ170", "ALQ151"]] = 0
df.loc[df["ALQ121"] == 0, ["ALQ130", "ALQ142", "ALQ270", "ALQ280", "ALQ170"]] = 0

2. Building the modeling dataset¶

We define the target from OCD150: employed = currently working or has a job but absent; not employed = everyone else. Critically, we first exclude retirees (OCD150 == 4 with reason OCQ383 == 3), since retirement is age-driven and would otherwise make the model detect age rather than employment. The remaining "not employed" class still mixes job-seekers with disabled/student/homemaker respondents, so we read it as "not employed (excl. retired)" rather than strict unemployment. We then drop rows with no employment label and remove leaky/duplicative occupation columns, leaving the numeric lifestyle variables as features X.

In [31]:

We check multicollinearity with VIF, iteratively dropping any feature with VIF > 5 (protecting PAD680), since collinearity would destabilize the logistic-regression coefficients we interpret later.

In [32]:
from statsmodels.stats.outliers_influence import variance_inflation_factor

# VIF needs complete data, so work on a median-imputed copy of the features.
# (The real pipeline imputes after the train/test split below.)
X_vif = X.fillna(X.median())

# Report highly correlated pairs for intuition (e.g. ALQ121 / ALQ280).
c = X.corr().abs()
pairs = c.where(np.triu(np.ones(c.shape), k=1).astype(bool)).stack()
print("Correlated pairs (|r| > 0.8):")
print(pairs[pairs > 0.8].sort_values(ascending=False).to_string() or "  none")

# Iteratively drop the highest-VIF feature until all <= 5; never drop PAD680.
PROTECTED = {"PAD680"}
features = list(X_vif.columns)
dropped = []
while True:
    vif = pd.Series([variance_inflation_factor(X_vif[features].values, i)
                     for i in range(len(features))], index=features)
    candidates = vif.drop(index=PROTECTED & set(features))
    if candidates.max() <= 5:
        break
    worst = candidates.idxmax()
    dropped.append((worst, round(candidates.max(), 2)))
    features.remove(worst)

print("\nDropped (feature, VIF at removal):", dropped or "none")
print("\nFinal VIF:")
print(vif.sort_values(ascending=False).round(2).to_string())

X = X[features]

5. Hypothesis testing¶

Beyond prediction, we ask which associations are statistically significant: we fit a logistic regression, run an omnibus likelihood-ratio test (does any feature predict employment?), then per-feature Wald tests with odds ratios and FDR correction for multiple comparisons.

In [44]:
import statsmodels.api as sm
from statsmodels.stats.multitest import multipletests

# Outcome as 0/1 (employed = 1), features median-imputed to keep the full sample.
# Note: imputation makes standard errors slightly optimistic vs. complete-case.
y01 = (y == "employed").astype(int)
X_test_hyp = sm.add_constant(X.fillna(X.median()))

result = sm.Logit(y01, X_test_hyp).fit(disp=False)

# 1. Omnibus likelihood-ratio test: H0 = no feature predicts employment.
print(f"n = {int(result.nobs)}")
print(f"Omnibus LR test: chi2 = {result.llr:.1f}, p = {result.llr_pvalue:.3e}")
print(f"McFadden pseudo-R^2 = {result.prsquared:.3f}")
print("=> reject H0; at least one feature predicts employment"
      if result.llr_pvalue < 0.05 else "=> fail to reject H0")

# 2. Per-feature Wald tests, with odds ratios, CIs, and FDR correction.
ci = result.conf_int()
table = pd.DataFrame({
    "coef": result.params,
    "odds_ratio": np.exp(result.params),
    "or_ci_low": np.exp(ci[0]),
    "or_ci_high": np.exp(ci[1]),
    "p_value": result.pvalues,
}).drop(index="const")
table["p_value_fdr"] = multipletests(table["p_value"], method="fdr_bh")[1]
table["significant"] = table["p_value_fdr"] < 0.05
table.sort_values("p_value").round(4)

Finally, we permutation-test the three non-linear models: by repeatedly shuffling the labels we build a null distribution of scores and check whether each model's real cross-validated performance beats chance.

In [45]:
from sklearn.model_selection import permutation_test_score, StratifiedKFold, cross_val_score
from sklearn.pipeline import make_pipeline
from IPython.display import display

# Pipelines so imputation (and scaling for KNN) happen inside each CV fold.
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
models = {
    "RandomForest": make_pipeline(
        SimpleImputer(strategy="median"),
        RandomForestClassifier(class_weight="balanced", random_state=42)),
    "KNN": make_pipeline(
        SimpleImputer(strategy="median"), StandardScaler(),
        KNeighborsClassifier()),
    "GradientBoosting": make_pipeline(
        SimpleImputer(strategy="median"),
        HistGradientBoostingClassifier(class_weight="balanced", random_state=42)),
}

# H0: the model predicts no better than chance (labels shuffled).
# permutation_test_score scores one metric (f1_macro); accuracy is added via a
# plain cross_val_score on the same folds (classes are ~balanced, so it's useful too).
perm_results = {}
for name, model in models.items():
    print(f"Running {name}...")
    score, _, pvalue = permutation_test_score(
        model, X, y, scoring="f1_macro", cv=cv,

6. Sensitivity analysis: does the target definition drive the result?¶

We re-run the models under two targets to see how much the conclusion depends on how retirees are treated: (A) employed vs not-employed, excluding retirees (our primary analysis), and (B) working vs not working, including retirees. If B looks much stronger, that gain reflects reintroduced age/life-stage signal and class rebalancing (the classes shift from ≈69/31 to ≈53/47) — not a genuinely stronger lifestyle effect.

Here, we flip the target to retired vs not-retired, using the same lifestyle features (no occupation columns, so no leakage). We expect this to be the most predictable target so far because retirement is age-driven and our features (sedentary time, physical activity, drinking) can be related to age.

The best model (GradientBoosting) reaches macro-F1 0.604 — about the same as the employment task (≈ 0.61) — and the logistic regression's pseudo-R² is 0.010, even lower than the employment model's 0.018. No model beats the majority-class accuracy (baseline 0.766; best is KNN at 0.727), although all the baseline's macro-F1 (0.434) and the permutation test is significant (p ≈ 0.01). Conclusion¶

We asked whether self-reported alcohol use and physical-activity behaviors can predict employment status. After excluding retirees (whose non-employment is age-driven rather than labor-market driven), the sample is 4,509 employed vs. 1,986 not employed (≈ 69% / 31%). The result is a statistically significant but weak correlation.

Some notes on our findings:

  • Prediction vs. baseline. Because ≈ 69% of the sample is employed, a majority-class baseline already scores 69.1% accuracy, and no model beats it on raw accuracy (RandomForest comes closest at 68.2%, GradientBoosting 65.3%). The models only pull ahead on a population-balanced metric: their macro-F1 (0.60–0.62) far exceeds the baseline's 0.41. In other words, they trade a negligible amount of accuracy to actually identify the minority "not employed" class instead of always guessing "employed".
  • Model comparison. RandomForest has the highest accuracy (0.682) but a lower macro-F1 (0.604), while GradientBoosting has the highest macro-F1 (0.623) at lower accuracy (0.653). On this imbalanced target, GradientBoosting's macro-F1 edge makes it the better all-round classifier.
  • Which features. Statistically, only the alcohol variables survive FDR correction — ALQ121 (past-year drinking frequency, OR ≈ 1.005 per drinking-day) and ALQ111 (ever drank, OR ≈ 1.71) were significant using Logistic Regression. The ML models rank physical-activity variables (vigorous/moderate minutes, sedentary time) highest by importance, so the predictive and inferential views disagree, meaning that no single behavior is a strong predictor.

Main takeaway: lifestyle behaviors are statistically significantly correlated with, but weak predictors of, employment status. They explain only a small share of the variation (pseudo-R² ≈ 0.02) and do not beat a trivial majority-class guess on accuracy, so they are not a practical basis for predicting employment. The same holds for retirement, confirming the limitation is the weak information content of these behaviors, not the specific target.

Limitations:

  • Assumed target — our "not employed" class combines job-seekers with disabled, student, and homemaker respondents, who may not be considered unemployed by other standards.
  • No demographic controls — age, sex, and income are not in the dataset, so we cannot fully separate lifestyle effects from demographics.
  • No survey weights — NHANES recommends sample weights (WTINT2YR) for population-level estimates; results here are unweighted.
  • Imputation — median-imputing within the hypothesis-test sample makes standard errors slightly optimistic.
